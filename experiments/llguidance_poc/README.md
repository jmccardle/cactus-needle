# llguidance constrained decoding for Needle — proof of concept

A/B test of the `DECODING_RIGOR.md` thesis on the **stock, un-fine-tuned** Needle checkpoint:
does an llguidance schema-grammar with jump-forward make tool-call output **more rigorous**
(only valid values) and **more efficient** (skip forced tokens)? Both, yes.

This is an ops check, not a paper. Greedy/argmax throughout, CPU JAX, 200 examples.

## What's here

| file | role |
|---|---|
| `tools_spec.py` | 10 tools + per-value regexes, the union Lark grammar builder, and semantic validators. One source of truth for grammar, model prompt, and scoring. |
| `needle_llg.py` | The SentencePiece→llguidance tokenizer bridge and the two decode drivers: `gen_unconstrained` (stock argmax) and `gen_constrained` (grammar mask + jump-forward). |
| `run_benchmark.py` | Runs both arms over all 200 examples, scores, writes `results.json` + `results.md`. |
| `data/*.json` | 20 `{query, arguments}` examples per domain (generated by Haiku subagents). |
| `results.md` | The generated report (per-domain + overall table). |

## The 10 domains (all "JSON but more rigorous")

`schedule_event` (YYYY-MM-DD + HH:MM) · `convert_currency` (decimal + ISO-4217 enum ×2) ·
`set_shipping_address` (US-state enum + 5-digit ZIP) · `rate_product` (int 1-5) ·
`set_brightness` (int 0-100) · `dial_phone` (NNN-NNN-NNNN) · `set_color` (#RRGGBB) ·
`set_thermostat` (int 50-90 + F/C enum) · `set_waypoint` (lat/lon ranges) ·
`set_timer` (0-23 / 0-59 / 0-59). The model is shown **all 10 tools on every query** and must
pick the right one; the grammar is a union over all 10, so it never leaks which tool to call.

## Results (stock / llg)

| scope | valid% | exact% | passes | speedup |
|---|---|---|---|---|
| **ALL** | **38 → 92** | 30 → 48 | 22.0 → 11.8 | **1.9×** |

Full per-domain table in `results.md`. Both hypotheses hold: **+54 pts validity, 1.9× fewer
forward passes.** Per-domain speedup ranges 1.0×–3.0× (highest where output is mostly structural,
e.g. `convert_currency` 2.7×, `rate_product` 3.0×; ~1.0× for `set_waypoint`, whose long free-form
coordinate digits leave little for jump-forward to skip).

## What the numbers actually mean (the honest part)

**Validity is a hard guarantee; correctness is not.** For the llg arm, `valid% == name%` (92 == 92):
*whenever the model picks the right tool, every key and value it emits is guaranteed well-formed and
in-domain.* The only residual "invalidity" is the model choosing the wrong tool — which the grammar
deliberately does not constrain (the model must decide). Contrast the stock arm, where even a
correct tool name (84%) drops to 38% valid because values are malformed.

The exact-match gap (48% for llg) is the model, un-fine-tuned, picking a **valid-but-wrong** value.
Illustrative:

- `"Please ship to San Francisco, California 94103"` → llg emits `"state":"SC"` — a real state code,
  just not CA. Grammar guarantees *a* valid state; it can't guarantee the *intended* one.
- `"Deliver to Cambridge, Massachusetts 02139"` → stock ran 48 passes and emitted
  `"state":"Cambridge"` (invalid, runaway); llg emitted a valid state in 12 passes (wrong one, but
  well-formed and 4× faster).
- `"Set up a conference call for December 25th, 2026…"` → stock put the **date in the time field**
  (`"time":"2026-12-25"`, structurally broken); llg produced correct field order and exact values.
- `"Turn brightness all the way up"` → **stock abstained** (`[]`), llg forced `percent:"90"`
  (expected 100). The grammar removes abstention — a robot always gets a call. This is exactly the
  `no_applicable_operation` branch argument from `DECODING_RIGOR.md` §2: if you want the model to be
  *able* to decline, the grammar must admit it.

Takeaway for the robotics motivation: the grammar is the safety floor (malformed commands become
structurally impossible — 38→92), and **fine-tuning is what would close the remaining valid-but-wrong
gap** (30→48 without any tuning; the two are complementary, as argued in `DECODING_RIGOR.md`).

## Jump-forward mechanics (efficiency, verified)

`passes` counts model forward passes. On Needle's un-cached decode each pass costs ~the same, so
wall-ms tracks passes (see `results.md`). The constrained arm injects grammar-forced token runs in a
single pass: the invariant envelope prefix ` [{"name":"`, the `","arguments":{"`/`":"`/`"}}]` glue,
and any value tail that becomes forced once disambiguated. That's the 22.0→11.8 drop. It is lossless
by construction — forced tokens have exactly one legal value, so masked-argmax would have chosen them
anyway (same property as the `f7c5864c` llama.cpp commit: byte-identical at temp 0).

## Implementation notes / caveats

- **SentencePiece dummy-prefix.** The load-bearing subtlety. llguidance re-tokenizes grammar-forced
  byte runs via the tokenizer; SentencePiece's `add_dummy_prefix` injects a spurious leading `▁`
  (space) into mid-stream forced runs (→ `rate _product`). Fix: a second SP processor with
  `add_dummy_prefix=False` for the bridge encoder (`needle_llg._no_dummy_prefix_sp`), plus injecting
  the one genuinely-dummy-prefixed run — the invariant ` [{"name":"` the model emits after
  `<tool_call>` — as a fixed forced prefix. This is the kind of thing a real integration must get
  right; it's documented in-code.
- **Values are quoted strings.** Needle emits every argument value as a JSON string, so the grammar
  constrains string *content* (e.g. `"stars":"5"`). A downstream caller parses to int/enum. Matches
  the model's native format.
- **Stock un-cached decode.** Both arms use Needle's existing full-buffer decode step (no KV cache),
  so absolute ms is slow and CPU-bound; the *ratio* is what's meaningful. A KV-cached decode (see
  `EXPORT_PATHS.md`) would cut per-pass cost ~300× on top of the pass-count win here.
- **Not fine-tuned.** Every number is the stock checkpoint. Tonight's point was the decoding
  machinery and the validity/speed deltas, not accuracy tuning.
